# DeepSeek Harness 本地应用

一个可以双击启动的 DeepSeek Harness 桌面入口。安装后不需要命令行，也不需要预先安装 Node.js。

## 安装

1. 双击 `DeepSeekHarness-Setup-*.exe`。
2. 在「选择目标位置」页面确认或修改安装目录，然后一路「下一步」。
   - 默认装到当前用户目录下，**不需要管理员权限**。
   - 请不要装到 `C:\Program Files` 这类受保护目录，程序需要在安装目录里写运行日志。
3. 安装完成后可以勾选「立即启动 DeepSeek Harness」。

Windows 可能弹出「已保护你的电脑」的蓝色提示——这是因为安装包没有购买代码签名证书，不是病毒。点「更多信息」→「仍要运行」即可。

## 使用

双击桌面上的 **DeepSeek Harness** 图标。会先弹出一个小窗，**转动的指示器 + 当前阶段文字**表示程序正在启动；服务就绪后该窗口自动关闭，浏览器随之打开。

- 首次启动约十几秒；窗口里的指示器在动就说明还活着，不用重复点击。
- 窗口下面那行字是启动器当前在做的事（检查运行时 / 同步插件 / 启动服务 / 等待就绪），启动中途失败重试时也会显示"…秒后重试（第 N 次）"，所以等待久一点也知道是在重试而不是卡死。
- 启动中途失败时窗口会关闭并弹出错误提示，提示里给的是**原因行**而不是堆栈尾巴。同时启动器会自己按 3/6/10/15/20/25/30 秒重试，所以多数"首次启动失败"会在窗口里自愈，用户看不到错误。
- 再次双击图标时，如果服务已经在运行，只会打开浏览器，不会重复启动，也不会再出现提示窗。
- 开始菜单里还有「停止 DeepSeek Harness」「检查更新」「查看日志」「命令行工具」「卸载 DeepSeek Harness」。
- 运行期间**不会弹出命令行黑窗口**：Harness 服务在一个隐藏的控制台里运行，它启动的子进程不会另开窗口。
- 想知道自己的数据存在哪：`dsh.cmd data`，或 **设置 → 数据管理**。

**首次使用需要填写 API Key**：打开界面后进入设置，填入你自己的 DeepSeek API Key。Key 保存在本机，不会随程序分发。

## 升级

程序内的是官方发布的 `@deepseek-ai/dsh` 包，可以从 npm 源升级，不需要重新下载安装包。

- **启动后自动提示**：应用启动、界面已经能用了之后，才会在后台检查新版本。发现新版本时弹出三个选项：
  - **立即升级** —— 下载并自动重启服务，失败会自动回滚。
  - **以后再说** —— 这次不升，下次启动仍会提示。
  - **不再提示此版本** —— 这个版本不再自动打扰你。
- **手动检查**：开始菜单 → DeepSeek Harness → **检查更新**。无论上面选过什么，手动检查都会告诉你**当前版本**、**当前通道解析出的版本**、是否需要升级，并列出**每个发布通道各自指向哪个版本**，允许升级。
- **只查看不升级**：`dsh.cmd check`。
- **无人值守升级**：`dsh.cmd update --yes`。

提示不会挡住启动：对话框弹出来的时候，界面早就可以正常使用了。

升级是安全的：新版本会先完整下载到一个临时目录，通过校验后才会替换正在用的版本；替换后会实际启动一次做健康检查，**启动失败会自动回滚到原来的版本**。

### 升级通道（为什么以前总是"已是最新版本"）

升级不是"跟着官网 releases 页面走"，而是跟着 npm 上的**发布通道**：

| `config.json` 的 `channel` | 解析成 |
|---|---|
| **`newest`（默认）** | 所有已发布版本里**最高的那个** |
| `latest` / `next` / `alpha` | 该 npm dist-tag 当前指向的版本 |
| 一个具体版本号（如 `0.1.6-alpha.1`） | 就是它 |

**以前默认跟着 `latest` 标签，所以会出现"官网明明有更新的版本，程序却说是最新"**：上游发布 `0.1.5-rc.2`、`0.1.6-alpha.1` 后并没有把 `latest` 移到它们上面（`latest` 仍指向 `0.1.5-rc.1`，新版本挂在 `next` 和 `alpha` 上）。旧版本只读 `dist-tags[channel]`，于是正确地报告"`latest` 就是 rc.1"——技术上没错，但对用户毫无用处。

现在的改动：

- 默认 `channel` 改成 **`newest`**，直接取已发布的最高版本，不再依赖上游何时移动标签；
- 检查更新时**列出每个通道各自指向哪个版本**，所以即使你固定跟随 `latest`，也能一眼看到 `next`/`alpha` 上有更新的东西；
- `channel` 写错时**明确报错并列出可用值**，而不是悄悄退回默认。

要回到"只跟官方推荐版本"，把 `channel` 改回 `latest` 即可。

### 多个 npm 源

升级会同时向配置里列出的**所有** npm 源查询版本，取其中最新的一个，因此某个源没同步、挂掉或很慢都不影响判断；下载则按顺序逐个尝试，**任何一个源下载失败都会自动换下一个**，全部失败才会报错。

| 默认顺序 | 源 |
|---|---|
| 1 | `https://registry.npmjs.org`（官方源，最完整） |
| 2 | `https://registry.npmmirror.com`（国内，快） |
| 3 | `https://mirrors.cloud.tencent.com/npm` |
| 4 | `https://mirrors.huaweicloud.com/repository/npm` |

官方源排第一是因为镜像虽然同步快，但有时只同步了主包、没同步它依赖的同批子包，这会让 npm 拒绝安装；后面的镜像作为兜底。国内如果嫌官方源慢，可以在 `config.json` 里把镜像调到前面，失败时仍会自动回退。

## 内置插件

安装包**自带并在首次启动时自动启用**三个插件，不需要联网安装：

| 插件 | 作用 |
|---|---|
| [dsh-market](https://github.com/dsh-market/dsh-market) | 插件市场：打开 **设置 → 插件市场**，浏览 2000+ 社区插件，一键安装、更新、卸载、切换主题。 |
| [dsh-deepseek-quota-bar](https://www.npmjs.com/package/dsh-deepseek-quota-bar) | 右下角可拖动的透明额度卡片：余额血条、今日/本月用量与当前对话花费。 |
| `dsh-data-manager` | **设置 → 数据管理**：看数据存在哪、占多少，并可把它整体迁移到别的盘（见「数据存在哪」）。 |

启用方式：启动器在启动服务前，把 `plugins\` 里的插件复制到当前 profile 的
`node_modules`（`%USERPROFILE%\.dsh\profiles\web\node_modules\`，也就是 `dsh plugin add`
会装到的位置），并把它写进 profile 清单 —— `dsh.profile.bundles` 加一层，
`dependencies` 记一条。也就是说，**和你自己装的插件完全一样**，插件市场里也能看到、
能自己更新。因此：

- 不需要联网，不需要 pnpm，也不需要你手工执行任何安装命令。
- 复制是幂等的：插件版本已经就位就什么都不做；版本不同才重新复制。
- 如果你自己用 `dsh plugin --profile web add dshmarket` 装过同一个插件，启动器发现清单里已经有它，就不会重复添加。
- `plugins\` 在 `app\` 之外，所以程序自我升级（替换 `app\`）不会把它们删掉。
- 想彻底不要它们：删掉 `plugins\preinstalled.json` 里对应的名字，下次启动启动器会把 profile 清单里的条目一并摘掉；或者直接在**插件市场里卸载**它 —— 你手动删掉的插件，启动器不会再加回来。
- 卸载程序不会删除 `%USERPROFILE%\.dsh`，所以已经复制进 profile 的那份也不会被删——这是刻意的，`%USERPROFILE%\.dsh` 是你的数据目录。

启动器给自己定了一条硬规则：**只有复制成功的插件才会被写进清单**。profile 清单里写了一个
找不到的 bundle，`dsh` 会直接拒绝启动；所以源文件缺失时启动器会把条目摘掉，程序照常启动，
只是少了那个插件。

额度插件需要先填 API Key 才能读到余额；插件市场的「设置 → 插件 → 插件配置」里可以管理它们自己。

## 配置

安装目录下的 `config.json`：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `port` | `3080` | Web 服务端口，与别的程序冲突时改这里。 |
| `dataDirectory` | 空 | 你的数据放在哪（会话、设置、API Key、插件）。留空＝`%USERPROFILE%\.dsh`。详见上一节。 |
| `workingDirectory` | 用户主目录 | 新建会话的默认工作目录。 |
| `registries` | 见上表 | npm 源列表，按顺序尝试；也可写单个字符串 `registry`。 |
| `channel` | `newest` | 升级跟随哪个通道：`newest`（已发布的最高版本）/ `latest` / `next` / `alpha`，或一个具体版本号。详见「升级通道」。 |
| `checkUpdates` | `true` | 启动时是否检查新版本；改为 `false` 可完全关闭。 |
| `updateCheckHours` | `6` | 两次联网检查之间的最小间隔（小时）。 |

改完需要重启应用生效（开始菜单 →「停止」后再双击图标）。

## 开机自启

```bat
dsh.cmd autostart on      :: 开启
dsh.cmd autostart off     :: 关闭
dsh.cmd autostart status  :: 查看
```

也可以手动把桌面快捷方式复制到 `shell:startup` 打开的文件夹。

## 数据存在哪

**所有你的东西都在一个目录里**，默认是：

```
%USERPROFILE%\.dsh
```

也就是 `C:\Users\<你的用户名>\.dsh`。里面：

| 内容 | 位置 |
|---|---|
| 会话记录（对话历史） | `sessions\` |
| 设置 | `settings.yaml` |
| API Key 与凭据 | `.credentials.yaml` |
| 上传的图片/附件 | `attachments\` |
| 插件 profile（预装插件就装在这里） | `profiles\` |
| 其它持久化数据 | `storages\`、`llm-deepseek\` |

随时可以问程序自己：

```bat
dsh.cmd data           :: 打印数据目录、来源、占用大小、子目录
dsh.cmd data open      :: 直接在资源管理器里打开它
```

或者打开界面：**设置 → 数据管理**。那一页显示同样的信息，并且可以直接**迁移**（见下）。

### 换到别的盘（防占满 C 盘）

界面里 **设置 → 数据管理** → 填一个新目录（例如 `D:\dsh-data`）→ 点「迁移到该目录」：

1. 插件把当前数据**完整复制**到新目录（跳过指向安装目录的 junction，那些是每次启动都会重建的索引）；
2. 复制完后核对文件数与字节数；
3. 改写安装目录下 `config.json` 的 `dataDirectory`；
4. 点「立即重启应用」生效（或手动：开始菜单 →「停止」→ 再双击图标）。

要点：

- **只复制，不删除**：原目录原样保留。确认新位置一切正常后，再自己删掉旧的。
- 目标目录必须是**空目录或尚不存在**，避免和已有数据混在一起。
- 迁移期间**尽量不要使用应用**，正在写入的会话可能落在复制开始之后。
- 也可以用命令行方式：停掉服务 → 把 `.dsh` 整个复制到新位置 → 改 `config.json` 的 `dataDirectory` → 启动。

### 固定到别的位置

数据目录按以下顺序决定，**只有一个答案，不会两个进程读不同地方**：

| 优先级 | 来源 |
|---|---|
| 1 | `config.json` 里的 `dataDirectory`（写绝对路径，例如 `D:\dsh-data`） |
| 2 | 环境变量 `DSH_HOME`（`dsh` 自己的约定；本机没设就不用管） |
| 3 | 默认 `%USERPROFILE%\.dsh` |

按 1 改完需要重启应用生效。启动器会把最终选定的目录**显式传给服务进程**，所以启动器和 Harness 服务永远读同一个位置；`dsh.cmd status` 和 `dsh.cmd data` 都会把它打印出来，并说明是哪个来源决定的。

- **升级、重新安装、卸载都不会动这个目录**：卸载只删程序本身，数据要你自己删。
- 想把数据搬到别的盘：先在「设置 → 停止」里停掉服务，把 `.dsh` 整个目录复制过去，在 `config.json` 里把 `dataDirectory` 指过去，再启动。路径里不要带 `%` 或中文以外的特殊字符更容易排查。
- 只改 `dataDirectory` 而旧目录还在，程序不会自动搬数据，也不会读旧目录——所以搬完再改，或者改完手动把旧目录内容复制过去。

## 卸载

「设置 → 应用 → 已安装的应用」里找到 DeepSeek Harness 卸载，也可以直接运行安装目录下的 `unins000.exe`（开始菜单里也有「卸载 DeepSeek Harness」）。卸载只删除程序本身，`%USERPROFILE%\.dsh` 需要手动删除。

**卸载后重新安装**会回到默认目录（记忆会随卸载一起清掉）；**直接重新安装/覆盖安装**则会回到上次装的位置。

## 再次安装会记住上次的位置

双击安装包时，「选择目标位置」页面会**自动填好上次安装的目录**，直接点「下一步」就是覆盖安装/更新，不用每次重新选。

程序同时记两处，因为它们的失效方式不同：

1. Windows 卸载项里的安装位置（「应用和功能」用的那条记录）；
2. 安装程序自己写的标记 `HKCU\Software\DeepSeek Harness` → `InstallDir`。

第二处是为了对付清理软件：这类工具常把「无效的卸载项」一并清掉——注册表里看不到卸载记录时，第一处就没了，安装程序便只能回到默认目录，这正是"每次都要重选"的常见原因。标记指向的目录如果已经没有 `unins000.exe`（比如被手动删了），安装程序会忽略它、回到默认目录，不会把你带进一个空壳路径。

手动指定 `/DIR="..."` 时以你指定的为准。

## 常见问题

| 现象 | 处理 |
|---|---|
| 提示「端口 3080 已被其他程序占用」 | 改 `config.json` 里的 `port`，或结束占用该端口的程序。 |
| 浏览器显示 `dsh web authentication required` | 浏览器登录凭据失效了（例如清理过浏览器数据）。用「停止」结束服务，再双击图标重新启动即可。 |
| 点击「停止」后服务仍在运行 | 正常情况下会连同一并结束。若提示无法确定进程号，请在启动它的终端里按 Ctrl+C。 |
| 启动很慢或失败 | 开始菜单 →「查看日志」，看安装目录下 `logs\dsh-web.log` 的末尾；失败弹窗里已经摘出了出错原因，不再只给一段堆栈。 |
| 弹窗提示「Cannot find package … imported from …\profiles\…」 | 这是 profile 的模块索引指向了以前那个安装目录（卸载过、换过安装位置，或被清理软件删过）。启动器会**自动清理该索引并重试一次**，正常情况下你不需要处理。 |
| 「检查更新」提示连不上 npm 源 | 程序会把尝试过的源都列在提示里。检查网络，或在 `config.json` 的 `registries` 里换成本地可用的源。 |
| 某个源下载失败 | 不需要处理，会自动换下一个源重试；只有全部失败才会报错并保留当前版本。 |
| 提示「内置的 Node.js 运行时缺失」 | `runtime\node\node.exe` 被删除或被安全软件隔离。重新运行安装程序修复；程序不会退回使用系统里的 Node.js。 |
| `dsh.cmd` 提示 `The bundled Node.js runtime is missing` | 同上（命令行里的提示固定为英文，因为中文会让批处理解析出错）。 |
| 升级下载很慢 | 官方源在国内可能较慢；可在 `registries` 里把国内镜像调到前面。下载期间会显示进度窗口。 |
| 数据占到 C 盘了，想换盘 | 停掉服务 → 把 `%USERPROFILE%\.dsh` 整个复制到新位置（例如 `D:\dsh-data`）→ 在 `config.json` 里写 `"dataDirectory": "D:\\dsh-data"` → 启动。用 `dsh.cmd data` 确认生效。 |
| 改了 `dataDirectory` 但界面里没有以前的会话 | 十有八九是新目录里没有旧数据，而不是程序读错地方：`dsh.cmd data` 会打印它实际读的目录，和 `config.json` 里的对比一下。 |
| 重装/更新后还是要我重选安装位置 | `dsh.cmd status` 能看程序目录。安装包会优先用上次的位置；如果你手动删过安装目录或改过盘符，它就会回到默认目录（这是有意的，免得装进一个空壳路径）。 |

## 系统要求

- Windows 10 / 11 x64（ARM64 设备通过 x64 兼容层运行）。
- 不需要预装 Node.js、pnpm 或其他运行时。
- 需要能访问 DeepSeek API 的网络；升级需要能访问 npm 官方源。

## 关于内置的 Node.js

安装包自带一份**固定版本**的 Node.js（版本号记在 `runtime\node-runtime.json`），程序**只使用这一份**，不会去用你电脑上已经安装的 Node.js。

原因：程序依赖若干为特定 Node 版本编译的原生模块，换用别的版本会加载失败。固定之后，同一份安装包在任何电脑上的行为都一致——电脑上装没装 Node、装的是哪个版本，都不影响本程序。

如果这份内置运行时被杀毒软件删除、或安装时没有完整复制，程序会直接提示「内置的 Node.js 运行时缺失」并拒绝启动，而**不会**悄悄改用系统里的 Node——那样只会在运行中途以更难排查的方式出错。看到该提示时，重新运行安装程序修复即可。

## 安全边界

- Web 服务只监听本机回环地址 `127.0.0.1`，**不对外网或局域网开放**，也没有可开启的开关。同一局域网内的其他人无法访问你的 DSH。
- 浏览器访问需要一次性的登录凭据，登录状态保留 30 天。
- 程序不含任何 API Key，也不会把你的 Key 发送到除你配置的模型服务之外的地方。

    install-shortcuts.ps1     快捷方式损坏或丢失时，重新执行可修复
